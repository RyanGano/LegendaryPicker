# LegendaryPicker design plan

**Status:** Design confirmed on 2026-09-27. Implementation is tracked as GitHub issues under the "Legendary Picker v1" parent issue. Update this plan when a decision or verified fact changes.

## Product goal

Help a player prepare a legally configured game of Upper Deck's Marvel Legendary: pick a player count, get one random complete setup, and set it up from a checklist that explains rule-driven inclusions and exclusions.

## Decisions

- **Game:** Marvel Legendary First Edition core box (released November 2012) for v1. Expansions are added one box at a time in release order (#34); Dark City (June 2013) is the first (#40), then Fantastic Four (October 2013, #41) and Paint the Town Red (March 2014, #42). Legendary: Villains (July 2014, #72) is the second base game, on its own Villainous ruleset. Players choose which boxes to include per setup (#8). Base games are optional picks like any other box (#71, D1 in #34): a setup needs at least one base game, and the core box is never mandatory. An expansion's rules apply only when its box is included. Data and rules are organized so adding a box is mostly adding data.
- **Input:** One to five players. One player uses the First Edition core Solo mode, or in a Villainous setup the Villains rulebook's Solo (VIL pp.19-20; the rulebook titles it Advanced Solo Mode, but it is Villains' only one-player mode, so it is in scope). The core box's and expansions' optional Advanced Solo variants are excluded (D4).
- **Rule precedence:** Printed card text overrides the rulebook (a Scheme overrides Always Leads and the Solo setup). Otherwise the base Legendary rules apply. Never substitute Second Edition rules.
- **Generation (table draw):** Draw the Scheme from those allowed at the player count; then the Mastermind (from those that can complete it); then add the groups the Scheme and Mastermind require (Always Leads is ignored in Solo); then draw the remaining Villain and Henchman Groups from what is left; then any Henchman Groups the Scheme draws outside the Villain Deck; then draw the Heroes. Each draw is equally likely among the remaining options. No locking or player preferences. Legality only, never balance.
- **No eligible Scheme:** If no Scheme is allowed at the player count, explain it and let the player choose another count. This is unreachable with the core box alone but must hold once expansions exist.
- **Result:** The selected Scheme, Mastermind, Heroes, Villain Groups and Henchman Groups; per-component counts and totals for the Villain Deck and Hero Deck; the Wound, Bystander and S.H.I.E.L.D. Officer stacks (and Sidekicks once an included box has them); each player's starting deck; short rule notes with a citation label and source link. "Generate another" replaces the result. No card-by-card lists or rulebook walkthrough.
- **App boundary:** Generate and present setups only. No accounts, history, favorites, saved setups or game-state tracking.
- **Use context:** Mobile-first responsive web app, online only.
- **UX:** The page calls the API on load to wake it and to list the boxes. The player picks a count and ticks the boxes to include, base games listed above expansions. The core box is ticked on a first visit and can be unticked; the ticked boxes are remembered in `localStorage`, and remembered ids the API no longer lists are ignored. With no base game ticked, Generate is disabled and a line asks for one; with boxes of different rulesets ticked (the core box or a Heroic expansion with Villains), Generate is disabled and a line says they can't be combined yet (#72, until #73). Picks remembered under the old `legendaryPicker.expansions` key from before #71 move once into `legendaryPicker.boxes` with the core box, and the old key is removed. Then the player taps Generate. A loading state covers cold starts; errors show a Retry.
- **Architecture:** The C# Minimal API owns the catalog, rules and generator; the React app calls it. GitHub Pages hosts the frontend. The API runs on Azure App Service, Free F1 on Linux in West US 2, at $0 a month (decided 2026-09-27), as the web app named by the `AZURE_WEBAPP_NAME` repository variable; its resource names and hostname stay out of the repo. F1 has no Always On, so the app idles and cold-starts, and it has a daily CPU quota; the wake-up ping and loading state cover the cold start. An UptimeRobot monitor, set up by the owner outside the repo, keeps the app warm: it sends `HEAD /api/health` to the web app named by the `AZURE_WEBAPP_NAME` repository variable every 5 minutes and expects 200, so `/api/health` answers both GET and HEAD. If the CPU quota bites, lengthen the interval first. `.github/workflows/deploy-api.yml` runs `dotnet test` and then deploys the service on pushes to `main` that touch it, signing in to Azure through OIDC (no stored secret). The Pages build gets the API URL from the `VITE_API_BASE_URL` repository variable. The API is public, without sign-in, with basic rate limits. Any other Azure resource, or a SKU change, needs explicit user authorization.
- **Randomness in tests:** The generator takes an injectable random source. Tests use fixed sequences and assert exact results; no statistical tests. No public seed.
- **Game data:** Catalog and sourced setup rules live in versioned project data grouped by box. Scheme and Mastermind setup effects are structured data, not code keyed on card names. Changes ship through reviewed commits.
- **Setup generator:** `Setup/SetupGenerator` performs the table draw through an `IRandomSource` (production wraps `Random.Shared`). Each draw picks from the options left in catalog order: the Scheme, the Mastermind, each remaining Villain Group, each remaining Henchman Group, each Henchman Group outside the Villain Deck, each Hero. Every box file names its `ruleset` at the top level (`firstEdition` for the core box and the Heroic expansions, `villainous` for Legendary: Villains, #72). A setup includes at least one base game, and every included box must follow one ruleset: combining rulesets, including a Heroic expansion in a Villains setup, is future work (#73). The first included base game in catalog order supplies the setup rules; every included box contributes cards and stacks, in catalog order whatever order the boxes are named in. The Result names its `ruleset`; each rule note keeps naming its box. Box files went to `schemaVersion` 4 when `setup.ruleset` became required (#71), and to 5 when `ruleset` moved to the top of every box file and Solo's `twistKosHeroCostingAtMost` became the `solo.playRules` list (#72). A Scheme the included cards cannot complete (too few groups or Heroes, too few Bystanders or Twists, a required group not included) is dropped before the draw. A Scheme's required groups take their slots first; the Always Leads group takes a slot if one is left and is dropped otherwise (D1). If no Scheme is eligible, the generator returns NoEligibleScheme.
- **Setup effects (#36):** A Scheme's `setup` either sets a count (`heroes`, `henchmanCards`, `villainDeckBystanders`, `woundsPerPlayer`) or adds to one: `extraHeroes`, `extraVillainGroups`, `extraHenchmanGroups` and `extraVillainDeckBystanders`. A Mastermind can carry the same adding effects under its own optional `setup`. Every adding effect is a list of `{ players, value, source }` entries, like `twists`: `players: null` applies at every count, `[1]` only in Solo, and a count no entry names adds nothing. `henchmanCards` (#68) is a per-player-count list like `twists` that sets how many cards of each Henchman Group go in the Villain Deck, replacing the box's 10 or Solo's 3; the Villain Deck's Henchman line and total use it, and its rule note cites its source, or D2 in Solo. The service refuses to start (#54) if one of these lists (`twists`, a Scheme's `heroes` or `henchmanCards`, or an adding effect) names a player count twice (a `null` entry names every count), names a count outside 1–5 or none at all, or has a `value` below 1; `setup.playerCounts` rows are checked the same way for repeated or out-of-range `players`. Counts apply in this order: the player-count table or Solo, then the Scheme's set values, then the Scheme's additions, then the Mastermind's; each addition that applies gives a rule note citing its own source (usually `Card`), and never D2, since it adds to the Solo value rather than replacing it. Required groups still fill slots first. A Scheme is eligible only when at least one Mastermind completes it with the included cards, and the Mastermind is drawn from those that do. Box files went to `schemaVersion` 3 when `moves` replaced `heroCardsInVillainDeck` (#37).
- **Card moves (#37):** A Scheme's `setup.moves` lists cards it moves during setup. Each move is `{ card, to, count, perPlayer }`: `card` is `hero`, `henchman`, `bystander`, `wound`, `officer` or `sidekick`; `to` is `villainDeck`, `heroDeck`, `besideScheme` or `startingDecks`; `count` is a per-player-count list like `twists`, so Solo can have its own value; `perPlayer: true` multiplies the count by the player count. The card kind fixes where the cards come from: Hero cards from the Hero Deck, Henchmen from the drawn Henchman Groups in the Villain Deck, the rest from their shared stack. A move into the starting decks puts its count in each player's deck. The destination deck gains a line, the source deck shows the cards moved out (or the source stack shrinks), and the totals include both; each move that applies gives a rule note citing its count's source. A Scheme whose moves the included cards can't supply (too few Bystanders, Henchmen, Hero cards and so on) is dropped before the draw. The service refuses to start if a move goes to a stack, goes back where its cards come from, names its own source, or sets `perPlayer` on a move into the starting decks. `GET /api/setup` lists the moves as `moves`, each `{ card, from, to, count, total }`: `count` is what each destination gets and `total` what leaves the source. Secret Invasion's 12 Hero cards are the core box's one move.
- **Hero rules (#38):** A Hero can carry a `heroName` (for example "Jean Grey") when it shares its Hero Name with another Hero; without one, its own `name` is its Hero Name. A Scheme's `setup` can constrain the Hero Deck: `requiredHeroes` (`{ heroId, source }`, each filling a Hero slot as a required group fills a group slot), `heroCounts` (`{ team or heroName, atLeast or exactly, source }`), and `distinctHeroNames` (`{ value, source }`: no two Heroes, in or outside the Hero Deck, with the same Hero Name). A Scheme can also draw Heroes outside the Hero Deck with `outsideHeroes`: each entry is `{ to, count, hero or heroName or team }`, where `to` is `villainDeck`, `besideScheme` or `setAside`, `count` is a per-player-count list of how many Heroes, and the optional `hero`, `heroName` or `team` limits the draw; all of each Hero's cards go to `to`. The Heroes outside the Hero Deck are drawn after the Hero Deck's, from Heroes not in it. Every Hero draw picks from the Heroes that still leave the rest of the setup's Heroes drawable within these rules, and a Scheme whose Hero rules the included Heroes can't meet is dropped before the draw. Each rule that applies gives a rule note citing its source. The service refuses to start if a required or named Hero doesn't resolve, a team isn't a team term, a Hero count names both or neither of a team and a Hero Name or both or neither of `atLeast` and `exactly` (or `atLeast` below 1, `exactly` below 0), or an `outsideHeroes` entry goes anywhere else or is limited by more than one of `hero`, `heroName` and `team`. It also refuses Hero rules no draw can meet, since there is one of each Hero: an `outsideHeroes` entry that names a `hero` with a count above 1, two `outsideHeroes` entries that name the same `hero` at one player count, a Hero listed twice in `requiredHeroes`, or a Hero both in `requiredHeroes` and named by an `outsideHeroes` entry (#61). More generally, it refuses a Scheme whose own Hero choices already break its Hero rules at a player count it allows, whichever boxes are included: two required Heroes with one Hero Name under `distinctHeroNames`, more required Heroes matching an `exactly` count than it allows, or a named Hero that takes the only Hero Name a count needs (#63). The check treats every Hero the Scheme doesn't name as open, so a Scheme only another box's Heroes can complete still loads and is dropped from draws without that box. `GET /api/setup` lists them as `outsideHeroes`, each `{ hero, to, cards }` with `hero` a component; the Villain Deck's `outsideHeroCards` counts the cards that go into it, and its `total` includes them. These fields kept `schemaVersion` 3, since every new field is optional.
- **Henchmen outside the Villain Deck (#77):** A Scheme's `setup.outsideHenchmen` draws Henchman Groups outside the Villain Deck. Each entry is `{ to, cards }`: it draws one group from the included Henchman Groups the setup doesn't already use, after the Villain Deck's groups, and puts `cards` of its cards in `to`; the rest of that group stays out of the game. `to` is `heroDeck` only, and `cards` is a per-player-count list like `twists`, cited to its source (Solo uses the entry for `[1]`; Solo's 3 Henchmen per group applies only to the Villain Deck's groups). A Scheme is dropped before the draw when the included boxes don't have a Henchman Group left for each entry once the Villain Deck's slots are filled, or when `cards` is more than a Henchman Group holds. Each entry that applies gives a rule note ("Scheme draws 1 extra Henchman Group outside the Villain Deck and puts 6 of its Henchmen into the Hero Deck"). The service refuses to start if an entry goes anywhere but `heroDeck`, or its `cards` breaks the player-count list rules. `GET /api/setup` lists the groups as `outsideHenchmen`, each `{ group, to, cards }` with `group` a component, and the Hero Deck's `total` includes them. The Setup checklist lays each one out as its own line in the Hero Deck section. It is an optional field, so `schemaVersion` stays 4.
- **Card identity (#76):** Every card a setup names must tell the player which physical card to use (owner rule, 2026-09-29). The service refuses to start when two Heroes, Villain Groups, Henchman Groups, Masterminds or Schemes share a display `name` (ignoring case), naming both ids and files. A new version of a character gets a distinguishing name, printed card title first ("Symbiote Spider-Man"), or the title with its version in brackets when the title is the same ("Wolverine (X-Force)"); `heroName` keeps the shared character for Hero rules. When more than one box is included, the web app shows each drawn card's box under its name on the result cards, tiles and checklist rows. Reprints that are one physical card (G12) are not modelled yet, so none are exempt.
- **Setup endpoint:** `GET /api/setup?players=1..5&boxes=<ids>` returns one table draw as camelCase JSON with a `kind` field: `setup` (the Result, each chosen component as id, name and glossary `terms`, plus the setup's `glossary`) or `noEligibleScheme` (the player count and a message), both 200. A missing or invalid `players` returns a 400 ProblemDetails naming the range. `boxes` is a comma-separated list of box ids and defaults to `core`; an unknown id, a list with no base game, or boxes of different rulesets returns a 400 ProblemDetails under `boxes`. A setup body carries `ruleset` after `players`. When a setup includes more than one box, each rule note and glossary entry also carries `box`, the name of the box its rule or term comes from, and each component the name of the box it comes from; with one box the field is left out. `GET /api/boxes` lists every box as `id`, `name`, `baseGame` and `ruleset`. Each client IP gets 30 setups per fixed one-minute window, then 429. The client IP is the address App Service's front end forwards in `X-Forwarded-For`, trusted only from the front end's link-local hop (169.254.0.0/16), and an IPv6 client's whole /64 shares one budget; `/api/health` is unlimited so the frontend can wake the app. Responses carry `Cache-Control: no-store`.
- **Villainous setups (#72):** A setup's rule notes use its ruleset's words (`Setup/RulesetTerms`), and the web app names the checklist's parts the same way from the setup's `ruleset`: Plot for Scheme, Commander for Mastermind, Ally for Hero, Adversary Group for Villain Group, Backup Adversary group for Henchman Group, Adversary Deck and Ally Deck, Plot Twists and Command Strikes, and HYDRA Operatives and Soldiers for the starting deck (the Villains rulebook's equivalent terms, VIL p.21). The model and the API fields keep the First Edition names. A base game's `setup.extraHeroes` (a per-player-count list) adds Heroes to its table, which Villains uses for its 6th Ally with 5 players (VIL p.7); it gives no rule note, as the table doesn't. `setup.solo.playRules` lists the Solo play rules as `{ label, source }`, each a rule note "Solo: …" held to the setup-step label rules; the core box's is the KO after each Twist. A Scheme's `setup.bindingsPerPlayer` sets the Bindings stack, as `woundsPerPlayer` sets Wounds.
- **Setup steps (#39):** A Scheme's or Mastermind's `setup` can list `steps`: setup steps that change no count, each `{ label, source }`, for example `{ "label": "Place the Baby Hope token on the Scheme", "source": "Card" }`. Labels follow the glossary content rule: our own words, one short instruction, never card text; the service refuses to start on an empty label, a label over 15 words, a label one card lists twice, or a source key the box doesn't list. Every step applies at every player count. `GET /api/setup` lists the labels as `steps`, the Scheme's then the Mastermind's, and each step gives a rule note ("Scheme adds a setup step: …") citing its source; no count or total changes. The Setup checklist shows them as lines to tick under "Other setup steps", after the starting decks. Steps kept `schemaVersion` 3.
- **Glossary:** Each box file has a `glossary` of terms: Hero teams, Hero classes and keywords (`kind` `team`, `class` or `keyword`). A term has an id, a name, a summary, a `source` key from the box's `sources` and the `page` that defines it. Heroes list their `team` (null when unaffiliated, like Deadpool) and `classes`; every Hero, Villain Group, Henchman Group, Mastermind and Scheme lists the keywords its cards use in `terms`. A term is listed only when the rulebook defines it; which cards use it may come from C1/C2. The service refuses to start on a term reference that doesn't resolve to a term of the right kind, a duplicate term id, or a term with no summary, a summary over 40 words, a source the box doesn't link, or no page. `GET /api/setup` gives each component its `terms` (a Hero's team, then classes, then keywords) and adds a `glossary` of every term the setup uses, once each, with `id`, `name`, `kind`, `summary`, `citation` (for example "R p.9") and `link`; both are ordered teams, classes, keywords, each in catalog order.
- **Glossary content rule:** Summaries are original paraphrases in our own words: at most two short sentences (40 words), never quoted or closely reworded from the rulebook. Each carries a source and page that link to the full rule. Every expansion adds its glossary terms in the same change as its cards.
- **Rule notes and citations:** Each box file lists its source keys with links (`sources`), and `setup.rulings` records the sources of how rules combine: Always Leads fills a slot (R p.6), a required group displaces Always Leads (D1), a Scheme overrides Solo (D2); Villains cites VIL p.6 for the first and VIL p.18, which rules that a Plot beats Always Leads and Solo (Mass Produce War Machine Armor), for the other two. A note cites the value's own source, or D2 when a Scheme value replaces a Solo value. `Card` has no link. A note's link comes from the sources of the box whose rule it is (the Scheme's box for a Scheme effect, the base game for the rulings and Solo), since two boxes may use the same key for different documents. The service refuses to start if a box lists the same source key twice, or if a rule value, ruling or setup effect cites a key other than `Card` that its own box doesn't list.
- **Ids:** Every Hero, Villain Group, Henchman Group, Mastermind and Scheme has the id `<boxId>_<kind>_<name>`, for example `core_mastermind_dr-doom`. `boxId` is the declaring box's id (the core box is `core`), `kind` is one of `hero`, `villain`, `henchman`, `mastermind` or `scheme`, and `name` is kebab-case. Glossary terms use the kind `term` (`core_term_ambush`). Underscores separate the segments; hyphens stay inside a segment. References (Always Leads, a Scheme's required groups, glossary terms) use the full id, so a box can reference another box's groups and terms. The service refuses to start if an id is malformed or duplicated, or if a reference doesn't resolve to a group of the stated type; a reference into a box that isn't loaded names that box.
- **Expansion box files:** Only a base game's box file has a `setup` section; an expansion's has none. An expansion still lists its `sources`, `components`, cards and `glossary`.
- **Shared stacks (#35):** Each box's `components` lists what it adds to the shared stacks: `bystanders`, `wounds`, `officers`, `sidekicks`, and the Villainous `bindings`, `madameHydra` and `newRecruits`, each sourced, and left out when the box adds none. Bindings, Madame HYDRA and New Recruits are stacks of their own, since the Villains rulebook says they are not equivalent to Wounds and Officers (VIL p.21). A box's special cards of a stack (Special Bystanders, special Wounds or Officers) count toward that stack. The core box lists 30 Bystanders, 30 Wounds and 30 Officers (R p.22). Each stack in the Result is the sum over the included boxes, less the Bystanders the setup puts in the Villain Deck, or the size a Scheme sets (Legacy Virus's Wounds). A stack appears only when an included box has it and is otherwise left out of the response: a First Edition setup has no Bindings, Madame HYDRA or New Recruits, a Villains setup no Wounds or Officers, and only some boxes have Sidekicks. The Twist and Bystander eligibility checks use these combined counts. The service refuses to start if a base game box (one with a `setup` section) leaves out a stack its ruleset lays out: `bystanders`, `wounds` and `officers` under First Edition; `bystanders`, `bindings`, `madameHydra` and `newRecruits` under Villainous. Each generator capability is tested with made-up expansions under `LegendaryPickerService.Tests/Fixtures`; each real expansion also gets its own tests against its box file (Dark City: `DarkCityTests`; Fantastic Four: `FantasticFourTests`; Paint the Town Red: `PaintTheTownRedTests`; Legendary: Villains: `VillainsTests`), including a check that it changes no draw when it isn't included.

## First Edition core box

Counts (R p.22): 15 Heroes × 14 cards, 7 Villain Groups × 8, 4 Henchman Groups × 10, 4 Masterminds, 8 Schemes, 11 Scheme Twists, 5 Master Strikes, 30 Bystanders, 30 Wounds, 30 S.H.I.E.L.D. Officers, and per-player starting cards. Names confirmed by C1 and C2 against those counts:

- **Heroes:** Black Widow, Captain America, Cyclops, Deadpool, Emma Frost, Gambit, Hawkeye, Hulk, Iron Man, Nick Fury, Rogue, Spider-Man, Storm, Thor, Wolverine.
- **Villain Groups:** Brotherhood, Enemies of Asgard, HYDRA, Masters of Evil, Radiation, Skrulls, Spider-Foes.
- **Henchman Groups:** Doombot Legion, Hand Ninjas, Savage Land Mutates, Sentinel.
- **Masterminds (Always Leads):** Dr. Doom (Doombot Legion, a Henchman Group), Loki (Enemies of Asgard), Magneto (Brotherhood), Red Skull (HYDRA).

### Glossary terms (R pp.6-18)

- **Teams (R p.18):** Avengers (Black Widow, Captain America, Hawkeye, Hulk, Iron Man, Thor), X-Men (Cyclops, Emma Frost, Gambit, Rogue, Storm, Wolverine), S.H.I.E.L.D. (Nick Fury), Spider Friends (Spider-Man, per C1 and C2). Deadpool is unaffiliated.
- **Classes (R p.18):** Covert, Instinct, Ranged, Strength, Tech. Each Hero's classes come from C1 and C2.
- **Keywords:** Always Leads (R p.6), Ambush (R p.9), Escape (R p.9), Fight (R p.13), Master Strike (R p.10), Mastermind Tactic (R p.14), Rescue a Bystander (R p.15), Scheme Twist (R p.10). Every Villain and Henchman Group uses Fight; every Mastermind uses Always Leads, Fight, Master Strike and Mastermind Tactic; every Scheme uses Scheme Twist.
