# LegendaryPicker design plan

**Status:** Design confirmed on 2026-09-27. Implementation is tracked as GitHub issues under the "Legendary Picker v1" parent issue. Update this plan when a decision or verified fact changes.

## Product goal

Help a player prepare a legally configured game of Upper Deck's Marvel Legendary: pick a player count, get one random complete setup, and set it up from a checklist that explains rule-driven inclusions and exclusions.

## Decisions

- **Game:** Marvel Legendary First Edition core box (released November 2012) for v1. Expansions are added one box at a time in release order (#34); Dark City (June 2013) is the first (#40), then Fantastic Four (October 2013, #41), Paint the Town Red (March 2014, #42), Guardians of the Galaxy (October 2014, #95), Fear Itself (March 2015, #96), the first Villainous expansion, and Secret Wars Volume 1 (August 2015, #113). Legendary: Villains (July 2014, #72) is the second base game, on its own Villainous ruleset. Players choose which boxes to include per setup (#8). Base games are optional picks like any other box (#71, D1 in #34): a setup needs at least one base game, and the core box is never mandatory. Heroic (First Edition) and Villainous boxes can be included together (#73), and the Scheme and Mastermind decide which rules apply (D-mixed, #85, #88), while every other card stays drawable whatever they are. An expansion's rules apply only when its box is included. Data and rules are organized so adding a box is mostly adding data.
- **Input:** One to five players. One player uses the First Edition core Solo mode, or, when a Villainous Plot or Commander is drawn (D-mixed), the Villains rulebook's Solo (VIL pp.19-20; the rulebook titles it Advanced Solo Mode, but it is Villains' only one-player mode, so it is in scope). The core box's and expansions' optional Advanced Solo variants are excluded (D4).
- **Rule precedence:** Printed card text overrides the rulebook (a Scheme overrides Always Leads and the Solo setup). Otherwise the base Legendary rules apply. Never substitute Second Edition rules.
- **Generation (table draw):** Draw the Scheme from those allowed at the player count; then the Mastermind (from those that can complete it); then add the groups the Scheme and Mastermind require (Always Leads is ignored in Solo); then draw the remaining Villain and Henchman Groups from what is left; then any Henchman Groups the Scheme draws outside the Villain Deck; then draw the Heroes. Each draw is equally likely among the remaining options. No locking or player preferences. Legality only, never balance.
- **No eligible Scheme:** If no Scheme is allowed at the player count, explain it and let the player choose another count. This is unreachable with the core box alone but must hold once expansions exist.
- **Result:** The selected Scheme, Mastermind, Heroes, Villain Groups and Henchman Groups; per-component counts and totals for the Villain Deck and Hero Deck; the Bystander stack and each other stack something in the setup uses (#87); each player's starting deck; short rule notes with a citation label and source link. "Generate another" replaces the result. No card-by-card lists or rulebook walkthrough.
- **App boundary:** Generate and present setups only. No accounts, history, favorites, saved setups or game-state tracking.
- **Use context:** Mobile-first responsive web app, online only.
- **UX:** The page calls the API on load to wake it and to list the boxes. The player picks a count and ticks the boxes to include, base games listed above expansions. The core box is ticked on a first visit and can be unticked; the ticked boxes are remembered in `localStorage`, and remembered ids the API no longer lists are ignored. With no base game ticked, Generate is disabled and a line asks for one. Boxes of different rulesets can be ticked together (#73) once a base game with rules for mixing them is ticked too; until then Generate is disabled and a line names the base games that have them (Legendary: Villains), except that an expansion that can be played under the other ruleset's base game (`playsWithOtherRulesets` in `/api/boxes`) needs no such base game, so the core box and Fear Itself alone can be drawn (D-heroic, #110); the result then says under its heading which rules it follows and why, with its citation. Picks remembered under the old `legendaryPicker.expansions` key from before #71 move once into `legendaryPicker.boxes` with the core box, and the old key is removed. Then the player taps Generate. A loading state covers cold starts; errors show a Retry.
- **Architecture:** The C# Minimal API owns the catalog, rules and generator; the React app calls it. GitHub Pages hosts the frontend. The API runs on Azure App Service, Free F1 on Linux in West US 2, at $0 a month (decided 2026-09-27), as the web app named by the `AZURE_WEBAPP_NAME` repository variable; its resource names and hostname stay out of the repo. F1 has no Always On, so the app idles and cold-starts, and it has a daily CPU quota; the wake-up ping and loading state cover the cold start. An UptimeRobot monitor, set up by the owner outside the repo, keeps the app warm: it sends `HEAD /api/health` to the web app named by the `AZURE_WEBAPP_NAME` repository variable every 5 minutes and expects 200, so `/api/health` answers both GET and HEAD. If the CPU quota bites, lengthen the interval first. `.github/workflows/deploy-api.yml` runs `dotnet test` and then deploys the service on pushes to `main` that touch it, signing in to Azure through OIDC (no stored secret). The Pages build gets the API URL from the `VITE_API_BASE_URL` repository variable. The API is public, without sign-in, with basic rate limits. Any other Azure resource, or a SKU change, needs explicit user authorization.
- **Randomness in tests:** The generator takes an injectable random source. Tests use fixed sequences and assert exact results; no statistical tests. No public seed.
- **Game data:** Catalog and sourced setup rules live in versioned project data grouped by box. Scheme and Mastermind setup effects are structured data, not code keyed on card names. Changes ship through reviewed commits. The release-order collection queue and per-product research records are tracked in [`Docs/BoxResearch/README.md`](BoxResearch/README.md); collected facts for a new product go in its own `Docs/BoxResearch/<slug>.md` file, separate from the runtime box JSON.
- **Setup generator:** `Setup/SetupGenerator` performs the table draw through an `IRandomSource` (production wraps `Random.Shared`). Each draw picks from the options left in catalog order: the Scheme, the Mastermind, each remaining Villain Group, each remaining Henchman Group, each Henchman Group outside the Villain Deck, each Hero. Every box file names its `ruleset` at the top level (`firstEdition` for the core box and the Heroic expansions, `villainous` for Legendary: Villains, #72). A setup includes at least one base game. Every box file has an `about.released` (year-month such as `2014-10`, with a `source`, key Q), which `/api/boxes` sorts by after putting base games first (#106; box files went to `schemaVersion` 7). The catalog order the draw uses is unchanged. Later box facts (#104: description, first-published year) belong in the same `about` section, with the year read from `released` rather than a second date. Boxes of different rulesets can be included together only when an included base game has rules for mixing them (`setup.mixing`, see Mixed setups); otherwise the setup is refused. Each ruleset's rules come from its first included base game in catalog order; every included box contributes cards, in catalog order whatever order the boxes are named in. The Result names its `ruleset`; each rule note keeps naming its box. Box files went to `schemaVersion` 4 when `setup.ruleset` became required (#71), and to 5 when `ruleset` moved to the top of every box file and Solo's `twistKosHeroCostingAtMost` became the `solo.playRules` list (#72). A Scheme the included cards cannot complete (too few groups or Heroes, too few Bystanders or Twists, a required group not included) is dropped before the draw. A Scheme's required groups take their slots first; the Always Leads group takes a slot if one is left and is dropped otherwise (D1). If no Scheme is eligible, the generator returns NoEligibleScheme.
- **Setup effects (#36):** A Scheme's `setup` either sets a count (`heroes`, `henchmanCards`, `villainDeckBystanders`, `woundsPerPlayer`) or adds to one: `extraHeroes`, `extraVillainGroups`, `extraHenchmanGroups` and `extraVillainDeckBystanders`. A Mastermind can carry the same adding effects under its own optional `setup`. Every adding effect is a list of `{ players, value, source }` entries, like `twists`: `players: null` applies at every count, `[1]` only in Solo, and a count no entry names adds nothing. `henchmanCards` (#68) is a per-player-count list like `twists` that sets how many cards of each Henchman Group go in the Villain Deck, replacing the box's 10 or Solo's 3; the Villain Deck's Henchman line and total use it, and its rule note cites its source, or D2 in Solo. The service refuses to start (#54) if one of these lists (`twists`, a Scheme's `heroes` or `henchmanCards`, or an adding effect) names a player count twice (a `null` entry names every count), names a count outside 1–5 or none at all, or has a `value` below 1; `setup.playerCounts` rows are checked the same way for repeated or out-of-range `players`. Counts apply in this order: the player-count table or Solo, then the Scheme's set values, then the Scheme's additions, then the Mastermind's; each addition that applies gives a rule note citing its own source (usually `Card`), and never D2, since it adds to the Solo value rather than replacing it. A Scheme rule overrides a normal rule unless the rules say otherwise, so a Scheme that sets a count replaces the Solo count and a Scheme's "+N Heroes" applies on top of it (owner decision D-readings, #92). Required groups still fill slots first. A Scheme is eligible only when at least one Mastermind completes it with the included cards, and the Mastermind is drawn from those that do. Box files went to `schemaVersion` 3 when `moves` replaced `heroCardsInVillainDeck` (#37).
- **Card moves (#37):** A Scheme's `setup.moves` lists cards it moves during setup. Each move is `{ card, to, count, perPlayer }`: `card` is `hero`, `henchman`, `bystander`, `wound`, `officer`, `sidekick`, `binding` or `twist` (#96); `to` is `villainDeck`, `heroDeck`, `besideScheme`, `startingDecks` or `setAside` (a stack of their own, such as Intergalactic Kree Nega-Bomb's Nega-Bomb Deck of 6 Bystanders, #95); `count` is a per-player-count list like `twists`, so Solo can have its own value; `perPlayer: true` multiplies the count by the player count. The card kind fixes where the cards come from: Hero cards from the Hero Deck, Henchmen from the drawn Henchman Groups in the Villain Deck, Twists from those the Villain Deck and the Scheme don't use (`twists`, counted against the boxes' Twists with the Scheme's own), the rest from their shared stack (a moved Binding means the Scheme uses Bindings, as a moved Wound means Wounds). A move into the starting decks puts its count in each player's deck. The destination deck gains a line, the source deck shows the cards moved out (or the source stack shrinks), and the totals include both; each move that applies gives a rule note citing its count's source. A Scheme whose moves the included cards can't supply (too few Bystanders, Henchmen, Hero cards and so on) is dropped before the draw. The service refuses to start if a move goes to a stack, goes back where its cards come from, names its own source, or sets `perPlayer` on a move into the starting decks. `GET /api/setup` lists the moves as `moves`, each `{ card, from, to, count, total }`: `count` is what each destination gets and `total` what leaves the source. Secret Invasion's 12 Hero cards are the core box's one move.
- **Hero rules (#38):** A Hero can carry a `heroName` (for example "Jean Grey") when it shares its Hero Name with another Hero; without one, its own `name` is its Hero Name. A Scheme's `setup` can constrain the Hero Deck: `requiredHeroes` (`{ heroId, source }`, each filling a Hero slot as a required group fills a group slot), `heroCounts` (`{ team or heroName, atLeast or exactly, source }`), and `distinctHeroNames` (`{ value, source }`: no two Heroes, in or outside the Hero Deck, with the same Hero Name). A Scheme can also draw Heroes outside the Hero Deck with `outsideHeroes`: each entry is `{ to, count, hero or heroName or team }`, where `to` is `villainDeck`, `besideScheme` or `setAside`, `count` is a per-player-count list of how many Heroes, and the optional `hero`, `heroName` or `team` limits the draw; all of each Hero's cards go to `to`. A Hero count counts only the Heroes in the Hero Deck, not those drawn outside it (owner decision D-readings, #92). The Heroes outside the Hero Deck are drawn after the Hero Deck's, from Heroes not in it. Every Hero draw picks from the Heroes that still leave the rest of the setup's Heroes drawable within these rules, and a Scheme whose Hero rules the included Heroes can't meet is dropped before the draw. Each rule that applies gives a rule note citing its source. The service refuses to start if a required or named Hero doesn't resolve, a team isn't a team term, a Hero count names both or neither of a team and a Hero Name or both or neither of `atLeast` and `exactly` (or `atLeast` below 1, `exactly` below 0), or an `outsideHeroes` entry goes anywhere else or is limited by more than one of `hero`, `heroName` and `team`. It also refuses Hero rules no draw can meet, since there is one of each Hero: an `outsideHeroes` entry that names a `hero` with a count above 1, two `outsideHeroes` entries that name the same `hero` at one player count, a Hero listed twice in `requiredHeroes`, or a Hero both in `requiredHeroes` and named by an `outsideHeroes` entry (#61). More generally, it refuses a Scheme whose own Hero choices already break its Hero rules at a player count it allows, whichever boxes are included: two required Heroes with one Hero Name under `distinctHeroNames`, more required Heroes matching an `exactly` count than it allows, or a named Hero that takes the only Hero Name a count needs (#63). The check treats every Hero the Scheme doesn't name as open, so a Scheme only another box's Heroes can complete still loads and is dropped from draws without that box. `GET /api/setup` lists them as `outsideHeroes`, each `{ hero, to, cards }` with `hero` a component; the Villain Deck's `outsideHeroCards` counts the cards that go into it, and its `total` includes them. These fields kept `schemaVersion` 3, since every new field is optional.
- **Masterminds outside the setup's own (#113):** A Scheme's `setup.outsideMasterminds` draws Masterminds besides its own. Each entry is `{ to, count, tactics }`: it draws `count` Masterminds (a per-player-count list like `twists`) from the included Masterminds other than the drawn one, after every other draw. `to` is `setAside`, where the Mastermind waits whole until the Scheme brings it into play (Dark Alliance adds it at Twist 1), or `villainDeck`, where `tactics` of each one's Tactics are shuffled in (Master of Tyrants: 3 Masterminds, 4 Tactics each); `tactics` is required for `villainDeck` and refused elsewhere. A Mastermind set aside doesn't bring its Always Leads group, since it arrives mid-game, but brings the parts it uses; Tactics in the Villain Deck play as Villains with no abilities, so their Mastermind brings no parts and no glossary terms. A Scheme is dropped before the draw when the included boxes have too few other Masterminds. Each entry gives a rule note ("Scheme draws 3 other Masterminds and shuffles 12 of their Tactics into the Villain Deck", "Scheme draws 1 other Mastermind and sets it aside"). `GET /api/setup` lists them as `outsideMasterminds`, each `{ mastermind, to, tactics }`, written only when there are any, and the Villain Deck's `mastermindTactics` (written only when above 0) counts in its `total`. The summary shows them as tiles under "Other Masterminds"; the checklist lays out the Tactics as a Villain Deck line and a set-aside Mastermind under Set aside. It is an optional field, so `schemaVersion` stays 7.
- **Henchmen outside the Villain Deck (#77):** A Scheme's `setup.outsideHenchmen` draws Henchman Groups outside the Villain Deck. Each entry is `{ to, cards }`: it draws one group from the included Henchman Groups the setup doesn't already use, never one already in the Villain Deck, in Solo too (owner decision D-readings, #92), after the Villain Deck's groups, and puts `cards` of its cards in `to`; the rest of that group stays out of the game. `to` is `heroDeck` only, and `cards` is a per-player-count list like `twists`, cited to its source (Solo uses the entry for `[1]`; Solo's 3 Henchmen per group applies only to the Villain Deck's groups). A Scheme is dropped before the draw when the included boxes don't have a Henchman Group left for each entry once the Villain Deck's slots are filled, or when `cards` is more than a Henchman Group holds. Each entry that applies gives a rule note ("Scheme draws 1 extra Henchman Group outside the Villain Deck and puts 6 of its Henchmen into the Hero Deck"). The service refuses to start if an entry goes anywhere but `heroDeck`, or its `cards` breaks the player-count list rules. `GET /api/setup` lists the groups as `outsideHenchmen`, each `{ group, to, cards }` with `group` a component, and the Hero Deck's `total` includes them. The Setup checklist lays each one out as its own line in the Hero Deck section. It is an optional field, so `schemaVersion` stays 4.
- **Cards beside the Scheme (#84):** A Scheme's `setup.cardsBeside` sets cards of one group beside it, whether or not that group is drawn. Each entry is `{ groupId, groupType, count, perPlayer, card }`: `count` is a per-player-count list like `twists`, `perPlayer: true` multiplies it by the player count, and the optional `card` names the one card of the group to set aside (Crown Thor's "Thor" of the Avengers). The cards leave the group, so a drawn group puts in the Villain Deck its usual share (all of a Villain Group; of a Henchman Group 10, the Scheme's count, or Solo's 3) or what is left of the group once its cards are beside the Scheme, whichever is fewer; the Villain Deck's lines keep the usual share, and its `total` takes the difference away. A group with no cards left can't be drawn into the Villain Deck, and nothing else changes which groups can be drawn: the cards beside the Scheme fill no group slot (VIL p.17, for Cage Villains' Cops), so Cops stay drawable as a Backup Adversary group until 5 players, when all 10 are beside the Plot. A Scheme is dropped before the draw when its group isn't included, when it sets more cards beside it than the group holds, or when it takes every card of a group the Scheme requires; a Mastermind is dropped when it takes every card of the group the Mastermind always leads. The group counts among the setup's cards for the parts it uses (#87) and its glossary terms. Each entry that applies gives a rule note citing its count's source ("Plot sets 4 Cops beside it, 2 per player", "Plot sets Thor of Avengers beside it"). The service refuses to start if the group reference doesn't resolve to a group of the stated type, the count breaks the player-count list rules, or `card` is blank. `GET /api/setup` lists the entries as `cardsBeside`, each `{ group, card, count, fromVillainDeck }` with `group` a component and `fromVillainDeck` how many fewer cards the group puts in the Villain Deck; the Setup checklist lays each one out as a line under "Beside the Scheme" and, when the group is drawn, shows the cards taken out of the Villain Deck as a line with no tick box. It is an optional field, so `schemaVersion` stays 6.
- **Card identity (#76):** Every card a setup names must tell the player which physical card to use (owner rule, 2026-09-29). The service refuses to start when two Heroes, Villain Groups, Henchman Groups, Masterminds or Schemes share a display `name` (ignoring case), naming both ids and files. A new version of a character gets a distinguishing name, printed card title first ("Symbiote Spider-Man"), or the title with its version in brackets when the title is the same ("Wolverine (X-Force)"); `heroName` keeps the shared character for Hero rules. When more than one box is included, the web app shows each drawn card's box under its name on the result cards, tiles and checklist rows. Reprints that are one physical card (G12) are not modelled yet, so none are exempt.
- **Setup endpoint:** `GET /api/setup?players=1..5&boxes=<ids>` returns one table draw as camelCase JSON with a `kind` field: `setup` (the Result, each chosen component as id, name and glossary `terms`, plus the setup's `glossary`) or `noEligibleScheme` (the player count and a message), both 200. A missing or invalid `players` returns a 400 ProblemDetails naming the range. `boxes` is a comma-separated list of box ids and defaults to `core`; an unknown id, a list with no base game, or boxes of different rulesets with no included base game that has rules for mixing them returns a 400 ProblemDetails under `boxes`, unless the base games are of one ruleset and every box of the other has an `otherRuleset` section (D-heroic, #110). A setup body carries `ruleset` after `players`: the ruleset whose rules it follows. A mixed setup also carries `mixed: true`, each component's `ruleset`, and `playerDeck.choices`; a setup whose included boxes follow more than one ruleset carries `rulesReason`, a rule note saying which rules it follows and why. A setup whose drawn cards use a part no included box supplies carries `standIns`, each `{ part, source, with }` (`with` null when nothing replaces it), so the checklist can mark the stack standing in (D-heroic, #110). Single-ruleset setups carry none of these. When a setup includes more than one box, each rule note and glossary entry also carries `box`, the name of the box its rule or term comes from, and each component the name of the box it comes from; with one box the field is left out. `GET /api/boxes` lists every box as `id`, `name`, `baseGame`, `ruleset`, `mixesRulesets` (true for a base game with `setup.mixing`, so the app can say why a mix of rulesets can't be drawn, #96) and `playsWithOtherRulesets` (true for an expansion with an `otherRuleset` section, which needs no such base game, #110). Each client IP gets 30 setups per fixed one-minute window, then 429. The client IP is the address App Service's front end forwards in `X-Forwarded-For`, trusted only from the front end's link-local hop (169.254.0.0/16), and an IPv6 client's whole /64 shares one budget; `/api/health` is unlimited so the frontend can wake the app. Responses carry `Cache-Control: no-store`.
- **Villainous setups (#72):** A setup's rule notes use its ruleset's words (`Setup/RulesetTerms`), and the web app names the checklist's parts the same way from the setup's `ruleset`: Plot for Scheme, Commander for Mastermind, Ally for Hero, Adversary Group for Villain Group, Backup Adversary group for Henchman Group, Adversary Deck and Ally Deck, Plot Twists and Command Strikes, and HYDRA Operatives and Soldiers for the starting deck (the Villains rulebook's equivalent terms, VIL p.21). The model and the API fields keep the First Edition names. A base game's `setup.extraHeroes` (a per-player-count list) adds Heroes to its table, which Villains uses for its 6th Ally with 5 players (VIL p.7); it gives no rule note, as the table doesn't. `setup.solo.playRules` lists the Solo play rules as `{ label, source }`, each a rule note "Solo: …" held to the setup-step label rules; the core box's is the KO after each Twist. A Scheme's `setup.bindingsPerPlayer` sets the Bindings stack, as `woundsPerPlayer` sets Wounds.
- **Mixed setups (#73, #85, #88):** A base game's optional `setup.mixing` holds the sources of its rules for mixing its ruleset with another: `rules` (which rules a draw follows), `pools`, `stacks` and `startingDeckChoice`. Legendary: Villains has one, citing D-mixed and VIL pp.20-21; the core box has none, so a setup with Heroic boxes and a Villainous box other than a base game with mixing rules is refused, unless the base games are of one ruleset and every box of the other has an `otherRuleset` section, as Fear Itself does (D-heroic, #110; see Fear Itself). The Scheme and Mastermind decide the rules (owner decision D-mixed, 2026-09-29, refined in #88): a Villainous Plot or Commander means the Villains rules (the Villainous table with its 6th Ally at 5 players, VIL p.7, and the Villains Solo, VIL pp.19-20); a Heroic Scheme and Mastermind mean the First Edition rules (the core table and the core Solo). The pair is drawn first and fixes the rules, so no later draw can change the rules its counts came from. Every other card (Heroes and Allies, Villain and Adversary Groups, Henchman Groups and Backup Adversary groups) is drawn from every included box whatever the pair, so none is locked out by it (owner rule, 2026-09-29, #88). A pair whose rules have no included base game (an all-Heroic pair with Villains and Heroic expansions but no core box) is dropped before the draw, unless its cards of that ruleset come from boxes with an `otherRuleset` section, which then follow the included base game's rules (D-heroic, #110). So with a mixing base game every such draw holds a Villainous Plot or Commander. Eligibility counts only the stacks of the pair's own rulesets, which every completion lays out. A setup whose drawn cards come from both rulesets is mixed: it draws its cards from shared pools (VIL pp.20-21), with no side limit on the Mastermind (the rulebook's limit is optional), and shuffles all Bystanders together (VIL p.21). Under the Villains rules a mixed setup also follows the rest of the combined setup of VIL p.21: it lays out the recruit stacks of every included base game (S.H.I.E.L.D. Officers, Madame HYDRA and New Recruits), which the players can recruit from, and, when base games of both rulesets are included, lets the players choose S.H.I.E.L.D. or HYDRA starting decks, which the checklist shows as a line to tick, with no pick by the generator. Under the First Edition rules its Villainous cards bring only the parts they use (D-uses, #88): the setup keeps the First Edition recruit stack (S.H.I.E.L.D. Officers) and starting deck with no choice, and adds, say, Bindings for an Adversary Group or Ally that uses them. Either way Wounds and Bindings are laid out only where a drawn card uses them (D-uses, #87, in place of the rulebook's "both stacks"). Each mixed-set rule gives a rule note citing its `setup.mixing` source. A mixed setup's notes and checklist name each card by its own ruleset's word (a Plot, a Mastermind) and a part holding both kinds by both words ("Villain or Adversary Groups", "Scheme Twists or Plot Twists"). With boxes of more than one ruleset included, the result's `rulesReason` names the card that decided the rules ("Villains rules: the Commander is Dr. Strange", or "Villains rules: the Plot is Crush HYDRA and the Commander is Dr. Strange") or says "First Edition rules: no Villainous Plot or Commander", cited D-mixed. Setups whose boxes follow one ruleset are unchanged. `MixedRulesetsTests` covers it against the real box files. `setup.mixing` is optional, so it kept `schemaVersion` 5.
- **Setup steps (#39):** A Scheme's or Mastermind's `setup` can list `steps`: setup steps that change no count, each `{ label, source }`, for example `{ "label": "Place the Baby Hope token on the Scheme", "source": "Card" }`. Labels follow the glossary content rule: our own words, one short instruction, never card text; the service refuses to start on an empty label, a label over 15 words, a label one card lists twice, or a source key the box doesn't list. Every step applies at every player count. `GET /api/setup` lists the labels as `steps`, the Scheme's then the Mastermind's, and each step gives a rule note ("Scheme adds a setup step: …") citing its source; no count or total changes. The Setup checklist shows them as lines to tick under "Other setup steps", after the starting decks. Steps kept `schemaVersion` 3.
- **Glossary:** Each box file has a `glossary` of terms: Hero teams, Hero classes and keywords (`kind` `team`, `class` or `keyword`). A term has an id, a name, a summary, a `source` key from the box's `sources` and the `page` that defines it. Heroes list their `team` (null when unaffiliated, like Deadpool) and `classes`; every Hero, Villain Group, Henchman Group, Mastermind and Scheme lists the keywords its cards use in `terms`. A term is listed only when the rulebook defines it; which cards use it may come from C1/C2. The service refuses to start on a term reference that doesn't resolve to a term of the right kind, a duplicate term id, or a term with no summary, a summary over 40 words, a source the box doesn't link, or no page. `GET /api/setup` gives each component its `terms` (a Hero's team, then classes, then keywords) and adds a `glossary` of every term the setup uses, once each, with `id`, `name`, `kind`, `summary`, `citation` (for example "R p.9") and `link`; both are ordered teams, classes, keywords, each in catalog order.
- **Glossary content rule:** Summaries are original paraphrases in our own words: at most two short sentences (40 words), never quoted or closely reworded from the rulebook. Each carries a source and page that link to the full rule. Every expansion adds its glossary terms in the same change as its cards.
- **Rule notes and citations:** Each box file lists its source keys with links (`sources`), and `setup.rulings` records the sources of how rules combine: Always Leads fills a slot (R p.6), a required group displaces Always Leads (D1), a Scheme overrides Solo (D2); Villains cites VIL p.6 for the first and VIL p.18, which rules that a Plot beats Always Leads and Solo (Mass Produce War Machine Armor), for the other two. A note cites the value's own source, or D2 when a Scheme value replaces a Solo value. `Card` has no link. A note's link comes from the sources of the box whose rule it is (the Scheme's box for a Scheme effect, the base game for the rulings and Solo), since two boxes may use the same key for different documents. The service refuses to start if a box lists the same source key twice, or if a rule value, ruling or setup effect cites a key other than `Card` that its own box doesn't list.
- **Ids:** Every Hero, Villain Group, Henchman Group, Mastermind and Scheme has the id `<boxId>_<kind>_<name>`, for example `core_mastermind_dr-doom`. `boxId` is the declaring box's id (the core box is `core`), `kind` is one of `hero`, `villain`, `henchman`, `mastermind` or `scheme`, and `name` is kebab-case. Glossary terms use the kind `term` (`core_term_ambush`). Underscores separate the segments; hyphens stay inside a segment. References (Always Leads, a Scheme's required groups, glossary terms) use the full id, so a box can reference another box's groups and terms. The service refuses to start if an id is malformed or duplicated, or if a reference doesn't resolve to a group of the stated type; a reference into a box that isn't loaded names that box.
- **Expansion box files:** Only a base game's box file has a `setup` section; an expansion's has none. An expansion still lists its `sources`, `components`, cards and `glossary`.
- **Shared stacks (#35):** Each box's `components` lists what it adds to the shared stacks: `bystanders`, `wounds`, `officers`, `sidekicks`, the Villainous `bindings`, `madameHydra` and `newRecruits`, and `shards` (Shard tokens, not cards, but laid out the same way; #95), each sourced, and left out when the box adds none. Bindings, Madame HYDRA and New Recruits are stacks of their own, since the Villains rulebook says they are not equivalent to Wounds and Officers (VIL p.21). A box's special cards of a stack (Special Bystanders, special Wounds or Officers) count toward that stack. The core box lists 30 Bystanders, 30 Wounds and 30 Officers (R p.22). Each stack in the Result is the sum over the included boxes of the drawn cards' rulesets, less the Bystanders the setup puts in the Villain Deck, or the size a Scheme sets (Legacy Virus's Wounds). Since #87 a stack other than Bystanders appears only when something in the setup uses it (see Parts by use) and is otherwise left out of the response: a First Edition setup has no Bindings, Madame HYDRA or New Recruits, a Villains setup no Wounds or Officers, and Wounds, Bindings and Sidekicks appear only when a drawn card uses them. The Twist and Bystander eligibility checks use these combined counts. The service refuses to start if a base game box (one with a `setup` section) leaves out a stack its ruleset lays out: `bystanders`, `wounds` and `officers` under First Edition; `bystanders`, `bindings`, `madameHydra` and `newRecruits` under Villainous. Each generator capability is tested with made-up expansions under `LegendaryPickerService.Tests/Fixtures`; each real expansion also gets its own tests against its box file (Dark City: `DarkCityTests`; Fantastic Four: `FantasticFourTests`; Paint the Town Red: `PaintTheTownRedTests`; Guardians of the Galaxy: `GuardiansOfTheGalaxyTests`; Fear Itself: `FearItselfTests`; Secret Wars Volume 1: `SecretWarsVolume1Tests`; Legendary: Villains: `VillainsTests`), including a check that it changes no draw when it isn't included.
- **Parts by use (#87, owner decision D-uses, 2026-09-29):** If a card in the setup uses another part of the game, that part is in the setup; a part nothing uses is left out. The parts so far are the shared stacks other than Bystanders (`part`: `wounds`, `officers`, `sidekicks`, `bindings`, `madameHydra`, `newRecruits`) and the Shard supply (`shards`, #95), which a box lists under `components.shards` and the setup lays out as a stack; every setup lays out Bystanders. A Hero, Villain Group, Henchman Group, Mastermind or Scheme lists the parts its card text takes cards from (gains, captures or turns into something) in an optional `uses` list of `{ part, source }`, cited `Card` and read from C1 and C2 as text. A card that only reacts to or KOs cards a player already has (Captain America, Wolverine, Iceman, Dark City's Paramedic) uses nothing. A Scheme also uses the stacks its Setup line sizes (`woundsPerPlayer` and `bindingsPerPlayer`) or moves cards from, without listing them. A base game's `setup.uses` lists what its rules use in every setup that follows them: the recruit stacks players can always recruit from, S.H.I.E.L.D. Officers under First Edition (R p.12) and Madame HYDRA and New Recruits under Villainous (VIL p.11); a mixed setup uses every included base game's (VIL p.21). A setup lays out a stack when its rules or a drawn card use it, sized as before from the boxes of the drawn cards' rulesets or by the Scheme. A Scheme that sizes one stack sizes that one only: Legacy Virus sets the Wound stack, and in a mixed game the Bindings stack is laid out at its full size only if a drawn card uses Bindings. When the boxes of the drawn cards' rulesets supply a stack no drawn card uses, the setup leaves it out with a rule note ("Leave out the Bindings stack: no drawn card uses it") citing the base game's `setup.rulings.unusedPartsLeftOut` (D-uses). So a First Edition setup whose cards give no Wounds (Solo with Skrulls, say) has no Wound stack (owner decision D-readings, #92). A card that uses a part no included box of its own ruleset supplies is dropped before the draw, like any other supply check: with Villains and Dark City but no core box, Mephisto, Stryfe and the Dark City cards that give Wounds are never drawn. The service refuses to start if a card or `setup.uses` lists a part twice, a use cites a source key its box doesn't list, or a base game's rules use a part the base game doesn't supply. `setup.uses` and `unusedPartsLeftOut` are required, so box files went to `schemaVersion` 6.
